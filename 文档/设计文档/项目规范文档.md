# 线上批发商城 H5 系统 — 项目规范文档

## 1. 代码规范

### 1.1 通用规范

- **语言**：全部使用 TypeScript，严格模式（`strict: true`）
- **缩进**：2 空格
- **引号**：单引号
- **分号**：不使用分号（配合 ESLint/Prettier 统一）
- **尾逗号**：全部保留
- **行宽**：120 字符
- **编码**：UTF-8

### 1.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名（组件） | PascalCase | `ProductCard.tsx` |
| 文件名（非组件） | kebab-case | `use-auth.ts`、`format-price.ts` |
| 目录名 | kebab-case | `product-detail/`、`order-list/` |
| 变量/函数 | camelCase | `getProducts`、`orderList` |
| 常量 | UPPER_SNAKE_CASE | `MAX_FILE_SIZE`、`ORDER_STATUS` |
| 类型/接口 | PascalCase | `ProductDetail`、`CartItem` |
| Vue 组件名 | PascalCase | `<ProductCard />` |
| CSS 类名 | kebab-case | `.product-card`、`.price-text` |
| API 路由 | kebab-case | `/api/product-skus` |

## 2. Git 规范

### 2.1 分支策略

| 分支 | 用途 |
|------|------|
| `main` | 生产环境分支，保持稳定 |
| `develop` | 开发主分支 |
| `feature/*` | 功能分支（如 `feature/cart`、`feature/orders`） |
| `fix/*` | 修复分支（如 `fix/stock-check`） |

### 2.2 Commit 消息规范

采用 Conventional Commits 格式：

```
<type>(<scope>): <subject>
```

**type 类型：**

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 Bug |
| docs | 文档变更 |
| style | 代码格式（不影响逻辑） |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试 |
| chore | 构建/工具变更 |

**scope 范围：**

| scope | 说明 |
|------|------|
| api | 后端 API |
| h5 | 用户端 H5 |
| admin | 管理后台 |
| db | 数据库 |
| shared | 共享代码 |

**示例：**
```
feat(api): add order creation endpoint with transaction
feat(h5): implement shopping cart page with quantity controls
feat(admin): add product management table with CRUD operations
fix(api): restore stock when order is cancelled
fix(h5): fix pull refresh not triggering on category page
docs(api): update API response format documentation
chore: add pnpm workspace configuration
```

## 3. API 调用规范

### 3.1 请求封装（H5 端示例）

```typescript
// h5/src/api/request.ts
import axios from 'axios'
import { useAuthStore } from '@/stores/useAuthStore'
import { showToast } from 'vant'
import router from '@/router'

const request = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 15000,
})

request.interceptors.request.use((config) => {
  const authStore = useAuthStore()
  if (authStore.session?.access_token) {
    config.headers.Authorization = `Bearer ${authStore.session.access_token}`
  }
  return config
})

request.interceptors.response.use(
  (response) => {
    const { data } = response
    if (data.code !== 0) {
      showToast(data.message || '请求失败')
      return Promise.reject(new Error(data.message))
    }
    return data
  },
  (error) => {
    if (error.response?.status === 401) {
      const authStore = useAuthStore()
      authStore.logout()
      router.push('/login')
    }
    showToast('网络异常，请稍后重试')
    return Promise.reject(error)
  }
)

export default request
```

```typescript
// h5/src/stores/useCartStore.ts
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import type { CartItem } from '@/types/cart'
import { getCart, addToCart, updateCart, deleteCart } from '@/api/cart'

export const useCartStore = defineStore('cart', () => {
  // state
  const items = ref<CartItem[]>([])
  const selectedIds = ref<number[]>([])

  // getters
  const totalPrice = computed(() => {
    return items.value
      .filter(item => selectedIds.value.includes(item.id))
      .reduce((sum, item) => sum + item.subtotal, 0)

    return items.value.length > 0 && selectedIds.value.length === items.value.length

  async function remove(id: number) { /* ... */ }
```

## 5. 组件规范

### 5.1 公共组件划分

| 组件 | 所属端 | 说明 |
|------|--------|------|
| ProductCard | H5 | 商品卡片（网格中的单个商品） |
| CartBadge | H5 | 购物车数量角标 |
| OrderStatusTag | H5 / Admin | 订单状态标签 |
| PriceDisplay | H5 | 价格显示组件（处理小数位） |
| EmptyState | H5 | 空状态占位组件 |
| ImageUpload | Admin | 图片上传组件 |
| RichTextEditor | Admin | 富文本编辑器 |
| StatusSwitch | Admin | 状态切换开关 |

### 5.2 组件编写原则

- 单一职责：一个组件只做一件事
- Props 类型化：使用 TypeScript interface 定义 props
- 事件命名：`on` + 动词（如 `onEdit`、`onDelete`、`onSelect`）
- 插槽（Vue）/ children（React）：用于灵活的内容分发
- 无副作用：组件不直接调用 API（通过 props 或 store 获取数据）

### 6.1 H5 端

## 7. 错误处理规范

### 7.1 API 层

| 层级 | 处理方式 |
|------|---------|
| Workers 全局 | errorHandler 中间件捕获所有未处理异常 |
| 业务逻辑 | 返回具体 code + message |
| 数据库操作 | try/catch，返回 500 + 通用错误信息 |

### 7.2 前端层

| 场景 | 处理方式 |
|------|---------|
| 网络异常 | Toast 提示 "网络异常" |
| 401 未登录 | 清除 Session → 跳转登录页 |
| 403 无权限 | Toast 提示 "无权限" |
| 业务错误（code != 0） | Toast 显示服务端 message |
| 表单校验 | 字段级错误提示（Vant / Ant Design Form） |

## 8. 性能规范

| 优化项 | 实现方式 |
|--------|---------|
| 图片懒加载 | Vant Lazyload 指令 / Intersection Observer |
| 列表分页 | 滚动加载（Vant List），每页 20 条 |
| 请求防抖 | 搜索输入 300ms 防抖 |
| 路由懒加载 | `() => import('@/views/xxx/index.vue')` |
| 组件按需引入 | unplugin-vue-components 自动按需加载 Vant |
| 包体积优化 | 避免引入完整 lodash，使用 lodash-es 或独立包 |

## 9. 安全规范

| 安全项 | 规范 |
|--------|------|
| 密钥管理 | 所有密钥通过环境变量注入，禁止硬编码 |
| Token 存储 | H5: localStorage，Admin: localStorage |
| 用户输入 | 前端校验 + 后端 zod schema 校验 |
| 富文本 | 渲染前 DOMPurify 过滤 XSS |
| 文件上传 | 前端 + 后端双重校验类型和大小 |
| 数据权限 | API 层校验 user_id 归属，防止越权访问 |
| 日志 | 禁止打印敏感信息（密码、Token、密钥） |
