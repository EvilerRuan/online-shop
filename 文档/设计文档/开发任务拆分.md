# 线上批发商城 H5 系统 — 开发任务拆分

## 开发阶段总览

| 阶段 | 名称 | 核心产出 |
|------|------|---------|
| Phase 1 | 基础设施搭建 | Monorepo + 数据库 + API 骨架 + 前端脚手架 |
| Phase 2 | 后端 API 开发 | 全部 API 接口实现 |
| Phase 3 | 用户端 H5 开发 | 全部用户端页面与交互 |
| Phase 4 | 管理后台开发 | 全部管理后台页面与功能 |
| Phase 5 | 联调测试与部署 | 端到端联调 + 上线部署 |

## Phase 1：基础设施搭建

### 1.1 Monorepo 项目初始化

| 任务ID | 任务名称 | 具体内容 |

| 1.1.3 | 共享类型定义 | 创建 shared/ 目录，定义公共类型（user, product, order, cart, address, category, api 响应） |

| 任务ID | 任务名称 | 具体内容 |

| 任务ID | 任务名称 | 具体内容 |

| 2.6.5 | 确认收货 | POST /api/orders/:id/confirm |
| 2.6.6 | 订单数量统计 | GET /api/orders/count（各状态计数） |

## 开发优先级建议

实际开发中建议按以下顺序逐步推进（纵向切分，每个切片可端到端验证）：

```
切片 1（最小可用）：
  基础设施 → 认证 API + 登录页 → 首页 API + 首页 → 分类 API + 分类页
  → 商品 API + 商品列表/详情 → 基本可浏览

切片 2（核心交易）：
  购物车 API + 购物车页 → 地址 API + 地址管理 → 订单 API + 确认订单
  → 订单列表/详情 → 可完成购物闭环

切片 3（管理后台）：
  Dashboard → 商品管理 → 分类管理 → 订单管理 → 用户管理
  → 首页配置 → 系统设置

切片 4（完善体验）：
  搜索页 → 个人中心 → 静态页面 → 优化 → 部署
```
