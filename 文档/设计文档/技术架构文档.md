# 线上批发商城 H5 系统 — 技术架构文档

## 1. 项目概述

开发一个线上批发商城 H5 系统，包含用户端（顾客选品下单）和管理后台（运营管理）。用户端通过手机浏览器、App 内嵌 WebView、小程序 web-view 访问；管理后台通过 PC 浏览器访问。

系统基于 Supabase（数据库、认证、存储）和 Cloudflare（部署、Workers API）构建。

| 服务 | 用途 |
|------|------|

| Supabase Storage | 文件/图片存储 |

### 2.5 选型原则

- **用户端选 Vue + Vant**：移动端 H5 场景成熟，Vant 组件（SwipeCell、Stepper、Tabs、PullRefresh 等）完美匹配电商需求，包体积小
- **管理后台选 React + Ant Design**：PC 端数据密集型界面（表格、表单、富文本编辑）Ant Design 优势明显
- **API 选 Hono on Workers**：需求指定 Cloudflare 部署，Hono 是目前 Workers 生态最成熟的 Web 框架
- **统一 TypeScript**：前后端全部使用 TypeScript，共享类型定义，减少前后端不一致

### 3.2 请求流程

**用户端请求流程：**
1. H5 应用发起 HTTP 请求到 Cloudflare Workers
2. Workers 中间件验证 Supabase JWT Token
3. 业务逻辑处理（库存校验、订单创建等）
4. Workers 通过 Service Role Key 操作 Supabase Database
5. 返回统一格式响应

**管理后台请求流程：**
1. Admin 应用发起 HTTP 请求到 Cloudflare Workers
2. Workers 中间件验证 JWT + 校验 role === admin
3. 业务逻辑处理
4. 操作 Supabase Database
5. 返回统一格式响应

**文件上传流程：**
1. 客户端选择图片 → 上传到 Cloudflare Workers
2. Workers 校验文件类型和大小（≤5MB，jpg/png/webp）
3. Workers 上传到 Supabase Storage
4. 返回文件 URL

## 6. 后端 API 架构

### 6.1 Hono 应用结构

```typescript
// api/src/index.ts
import { Hono } from 'hono'
import { cors } from 'hono/cors'
import { authMiddleware } from './middleware/auth'
import { adminMiddleware } from './middleware/admin'

const app = new Hono()

// 全局 CORS
app.use('*', cors())

// 公开路由（无需认证）
app.route('/api/auth', authRoutes)

// 用户端路由（需认证）
app.use('/api/*', authMiddleware)
app.route('/api/products', productRoutes)
app.route('/api/categories', categoryRoutes)
app.route('/api/cart', cartRoutes)
app.route('/api/orders', orderRoutes)
app.route('/api/address', addressRoutes)
app.route('/api/home', homeRoutes)
app.route('/api/upload', uploadRoutes)

// 管理后台路由（需认证 + admin 权限）
app.use('/api/admin/*', adminMiddleware)
app.route('/api/admin/dashboard', adminDashboardRoutes)
app.route('/api/admin/products', adminProductRoutes)
app.route('/api/admin/categories', adminCategoryRoutes)
app.route('/api/admin/orders', adminOrderRoutes)
app.route('/api/admin/users', adminUserRoutes)
app.route('/api/admin/home-config', adminHomeConfigRoutes)
app.route('/api/admin/settings', adminSettingsRoutes)

export default app
```

### 6.2 中间件设计

**authMiddleware（认证中间件）：**
1. 从 Header 提取 `Authorization: Bearer <token>`
2. 调用 Supabase `auth.getUser(token)` 验证 Token
3. 验证成功 → 将 user 信息注入 context
4. 验证失败 → 返回 `{ code: 401, message: "未登录" }`

**adminMiddleware（管理员权限中间件）：**
1. 先执行 authMiddleware 逻辑
2. 查询 profiles 表确认 `role === 'admin'`
3. 校验账号 `status === 'active'`
4. 非 admin → 返回 `{ code: 403, message: "无权限访问后台" }`

**errorHandler（全局错误处理）：**
1. 捕获所有未处理异常
2. 记录错误日志
3. 返回统一格式错误响应

### 6.3 统一响应格式

```typescript
// 成功响应
{
  "code": 0,
  "message": "success",
  "data": { ... }
}

// 分页响应
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [...],
    "total": 100,
    "page": 1,
    "page_size": 20
  }
}

// 错误响应
{
  "code": 401,
  "message": "未登录"
}
```

### 6.4 关键业务逻辑 — 订单创建（事务）

```
POST /api/orders
│
├── 1. 验证请求参数（收货地址ID、商品列表、备注）
│
├── 2. 开启数据库事务
│     │
│     ├── 3. 查询所有商品规格库存
│     │     │
│     │     ├── 库存充足 → 继续
│     │     │
│     │     └── 库存不足 → 回滚，返回 "xxx商品库存不足"
│     │
│     ├── 4. 扣减库存（UPDATE product_skus SET stock = stock - quantity）
│     │
│     ├── 5. 创建订单记录（INSERT orders）
│     │
│     ├── 6. 创建订单商品记录（INSERT order_items）
│     │
│     ├── 7. 更新商品销量（UPDATE products SET sales_count = sales_count + quantity）
│     │
│     └── 8. 清空购物车（DELETE cart WHERE user_id = ?）
│
└── 9. 提交事务 → 返回订单信息
```

### 6.5 关键业务逻辑 — 取消订单（恢复库存）

```
POST /api/orders/:id/cancel
│
├── 1. 验证订单存在且属于当前用户
│
├── 2. 验证订单状态为 pending_payment
│
├── 3. 开启事务
│     │
│     ├── 4. 更新订单状态 → cancelled
│     │
│     └── 5. 恢复库存（UPDATE product_skus SET stock = stock + quantity）
│
└── 6. 提交事务 → 返回更新后订单
```

## 7. 认证方案

### 7.1 认证流程

```
┌─────────────────────────────────────────────────────────────┐
│                    Supabase Auth 认证流程                     │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  管理后台创建用户：                                           │
│  Admin → POST /api/admin/users → Supabase Admin API         │
│         → 创建 auth.users + profiles 记录                    │
│                                                             │
│  用户登录（H5）：                                             │
│  H5 → POST /api/auth/login → Supabase auth.signInWithPassword│
│     → 返回 Session (access_token + refresh_token)           │
│     → 客户端存储到 localStorage                              │
│                                                             │
│  管理员登录（Admin）：                                         │
│  Admin → POST /api/admin/login → Supabase auth.signIn        │
│        → 校验 role === admin                                │
│        → 返回 Session                                       │
│                                                             │
│  Token 刷新：                                                │
│  客户端 → 过期前自动调用 supabase.auth.refreshSession()       │
│                                                             │
│  退出登录：                                                   │
│  客户端 → supabase.auth.signOut() → 清除本地存储             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 用户创建方式

管理员通过后台创建用户时，Workers API 使用 Supabase Service Role Key 调用 Admin API：

```typescript
// 1. 创建 Auth 用户
const { data: authUser } = await supabase.auth.admin.createUser({
  email: `${phone}@shop.local`,  // 手机号作为唯一标识
  password: initialPassword,
  phone: phone,
  user_metadata: { username, phone }
})

// 2. 创建 Profile 记录
const { data: profile } = await supabase
  .from('profiles')
  .insert({
    id: authUser.user.id,
    username,
    phone,
    role: 'user',
    status: 'active'
  })
```

## 8. 文件上传方案

### 8.1 上传流程

```
客户端选择图片
  │
  ├── 前端校验（类型: jpg/png/webp, 大小: ≤5MB）
  │
  ├── POST /api/upload (multipart/form-data)
  │
  ├── Workers 二次校验
  │
  ├── 生成唯一文件名（UUID + 扩展名）
  │
  ├── 上传到 Supabase Storage (bucket: uploads)
  │
  └── 返回文件 URL
      { "code": 0, "data": { "url": "https://xxx.supabase.co/storage/v1/object/public/uploads/xxx.jpg" } }
```

### 8.2 Storage Bucket 配置

| Bucket | 权限 | 用途 |
|--------|------|------|
| `uploads` | 公开读取，Service Role 写入 | 商品图片、Banner 图片 |

## 12. 安全策略

| 安全项 | 实现方式 |
|--------|---------|
| 接口认证 | Supabase JWT Token，每次请求校验 |
| 管理权限 | 中间件校验 role === admin |
| 数据隔离 | Supabase RLS 策略 + API 层 user_id 校验 |
| 文件上传 | 类型白名单 + 大小限制（5MB） |
| XSS 防护 | 富文本内容 DOMPurify 过滤 |
| CORS | Workers 层配置允许域名 |
| 敏感信息 | 环境变量管理，不硬编码密钥 |
