# 部署指南

## 前置条件

- Node.js >= 18
- pnpm >= 8
- Cloudflare 账号（用于 Workers 和 Pages）
- Supabase 项目已创建并配置好数据库迁移

## 项目架构

| 模块 | 技术栈 | 部署目标 |
|------|--------|----------|
| API | Hono + Cloudflare Workers | Cloudflare Workers |
| H5 用户端 | Vue 3 + Vant 4 | Cloudflare Pages / 静态托管 |
| Admin 管理后台 | React 18 + Ant Design 5 | Cloudflare Pages / 静态托管 |
| 数据库 | Supabase PostgreSQL | Supabase Cloud |

---

## 1. API 部署（Cloudflare Workers）

### 1.1 安装 Wrangler CLI

```bash
npm install -g wrangler
wrangler login
```

### 1.2 配置 Secrets

`wrangler.toml` 中已配置 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY`（非敏感信息）。

Service Role Key 需要通过 secret 方式注入：

```bash
cd api
wrangler secret put SUPABASE_SERVICE_ROLE_KEY
# 粘贴 Service Role Key，回车确认
```

### 1.3 部署

```bash
pnpm run deploy:api
# 或
cd api && npx wrangler deploy
```

部署成功后会获得一个 Workers URL，如：
`https://online-shop-api.<your-subdomain>.workers.dev`

### 1.4 验证

```bash
curl https://online-shop-api.<your-subdomain>.workers.dev/api/settings?key=site_name
```

## 2. H5 用户端部署

### 2.1 配置生产环境变量

在 `h5/.env.production` 中设置：

```env
VITE_API_BASE_URL=https://online-shop-api.<your-subdomain>.workers.dev/api
VITE_SUPABASE_URL=https://<your-project>.supabase.co
VITE_SUPABASE_ANON_KEY=<your-anon-key>
```

### 2.2 构建

```bash
pnpm run build:h5
```

构建产物在 `h5/dist/` 目录。

### 2.3 部署到 Cloudflare Pages

**方式一：CLI 部署**

```bash
npx wrangler pages deploy h5/dist --project-name=online-shop-h5
```

**方式二：Git 集成（推荐）**

1. 将代码推送到 GitHub
2. 在 Cloudflare Dashboard → Pages → Create a project → Connect to Git
3. 配置：
   - Build command: `pnpm run build:h5`
   - Build output directory: `h5/dist`
   - Environment variables: 填入上述 `VITE_*` 变量

### 2.4 自定义域名（可选）

在 Cloudflare Pages 项目设置中绑定自定义域名。

## 4. Supabase 配置检查

### 4.1 确认数据库迁移已执行

在 Supabase Dashboard → SQL Editor 中确认以下迁移已运行：
- `001_init_tables.sql` — 12 张表 + 索引 + 触发器
- `002_rls_policies.sql` — RLS 策略
- `003_seed_data.sql` — 初始数据

### 4.2 确认 Storage Bucket

确认 `uploads` bucket 已创建，并设置公开读取权限（用于商品图片展示）。

### 4.3 创建管理员账号

使用 `scripts/create-admin.js` 脚本或手动通过 Supabase Auth Admin API 创建管理员：

```bash
cd api && node ../scripts/create-admin.js <手机号> <密码> <用户名>
```

## 6. 环境变量汇总

### API（Cloudflare Workers）

| 变量名 | 位置 | 说明 |
|--------|------|------|
| SUPABASE_URL | wrangler.toml [vars] | Supabase 项目 URL |
| SUPABASE_ANON_KEY | wrangler.toml [vars] | Supabase 匿名 Key |
| SUPABASE_SERVICE_ROLE_KEY | wrangler secret | Supabase 服务角色 Key（敏感） |

### H5 / Admin（Cloudflare Pages）

| 变量名 | 说明 |
|--------|------|
| VITE_API_BASE_URL | API 服务地址（含 /api 前缀） |
| VITE_SUPABASE_URL | Supabase 项目 URL |
| VITE_SUPABASE_ANON_KEY | Supabase 匿名 Key |

## 7. 常见问题

### Q: Workers 部署后 CORS 报错
A: Hono 已配置 `cors()` 中间件，默认允许所有来源。如需限制，可在 `api/src/index.ts` 中配置 CORS 白名单。

### Q: 前端页面刷新后 404
A: Cloudflare Pages 默认支持 SPA fallback。如果使用其他静态托管（如 Nginx），需配置所有路由 fallback 到 `index.html`。

### Q: 图片上传失败
A: 确认 Supabase Storage 的 `uploads` bucket 已创建，且 Service Role Key 有写入权限。
