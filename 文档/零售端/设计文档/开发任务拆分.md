# 零售商城 — 开发任务拆分

## 开发阶段总览

| 阶段 | 名称 | 核心产出 |
|------|------|---------|
| Phase 1 | 数据库迁移 + shared 类型 | 8个迁移脚本(009-016) + shared 包扩展 |
| Phase 2 | API 基础设施 | 零售认证中间件 + 微信/验证码登录 + 积分公共函数 |
| Phase 3 | 零售端 API | 首页/商品/运费/订单/售后/积分/消息/推荐 全部接口 |
| Phase 4 | 管理后台 API | Dashboard扩展 + 运费/积分/售后/客服/零售用户/首页配置 CRUD |
| Phase 5 | 零售前端 | Taro 项目 + 全部页面（H5 + 小程序双端） |
| Phase 6 | 管理后台前端 | React 新增路由和菜单 + 6个零售管理页面 |
| Phase 7 | WebSocket 客服（可选） | Durable Objects 或 HTTP 轮询 |
| Phase 8 | 联调测试 | 端到端测试 + Bug 修复 |

## 开发优先级建议

实际开发中建议按以下顺序逐步推进（纵向切分，每个切片可端到端验证）：

```
切片 1（基础 + 可浏览）：
  数据库迁移(009-016) → shared 类型扩展 → 零售认证中间件 + 微信/验证码登录
  → 首页 API + 首页页面 → 商品 API + 商品列表/详情 → 基本可浏览

切片 2（核心交易）：
  运费 API + 运费计算 → 购物车 → 订单 API + 确认订单页 → 订单列表/详情
  → 地址管理 → 可完成零售购物闭环

切片 3（增值功能 + 管理后台）：
  售后 API + 售后页面 → 积分 API + 积分页面 → 推荐 API + 推荐页面
  → 客服消息 → 管理后台零售模块（Dashboard扩展 + 运费/积分/售后/客服/用户/首页配置 CRUD）

切片 4（完善体验）：
  个人中心 → 静态页面 → WebSocket客服(可选) → 小程序端适配
  → 管理后台扩展页面 → H5/小程序双端联调 → 全链路测试 → Bug 修复
```
