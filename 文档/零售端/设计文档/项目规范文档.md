# 零售商城 — 项目规范文档

## 1. 代码规范

### 1.1 通用规范

- **语言**：全部使用 TypeScript，严格模式（`strict: true`）
- **缩进**：2 空格
- **引号**：单引号
- **分号**：不使用分号（配合 ESLint/Prettier 统一）
- **尾逗号**：全部保留
- **行宽**：120 字符
- **编码**：UTF-8

### 1.2 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 文件名（组件） | PascalCase | `ProductCard.vue` |
| 文件名（非组件） | kebab-case | `use-auth.ts`、`format-price.ts` |
| 目录名 | kebab-case | `product-detail/`、`order-list/` |
| Taro 页面文件 | kebab-case 目录 + index.vue | `pages/product-detail/index.vue` |
| API 路由文件 | kebab-case | `product-skus.ts`、`order-list.ts` |
| 变量/函数 | camelCase | `getProducts`、`orderList` |
| 常量 | UPPER_SNAKE_CASE | `MAX_FILE_SIZE`、`ORDER_STATUS` |
| 类型/接口 | PascalCase | `ProductDetail`、`CartItem` |
| Vue 组件名 | PascalCase | `<ProductCard />` |
| CSS 类名 | kebab-case | `.product-card`、`.price-text` |
| API 路由 | kebab-case | `/api/product-skus` |

### 1.4 Taro 跨端规范

| 场景 | 规范 | 说明 |
|------|------|------|
| 平台判断 | `process.env.TARO_ENV` | 根据编译目标区分逻辑 |
| 本地存储 | `Taro.setStorageSync` / `Taro.getStorageSync` | 禁止使用 `localStorage` |
| 页面导航 | `Taro.navigateTo` / `Taro.switchTab` | 禁止使用 `window.location` |
| 分享功能 | 包裹在 `TARO_ENV === 'weapp'` 判断中 | H5 端无分享能力 |
| 网络请求 | `Taro.request` 或 axios + Taro adapter | 禁止直接使用 `fetch` / `XMLHttpRequest` |
| 路由跳转 | 使用 Taro 路由 API | 禁止使用 `vue-router` |
| 条件编译 | `#ifdef` / `#ifndef` 注释 | 仅在必要时使用 |

## 2. Git 规范

### 2.1 分支策略

| 分支 | 用途 |
|------|------|
| `main` | 生产环境分支，保持稳定 |
| `develop` | 开发主分支 |
| `feature/*` | 功能分支（如 `feature/retail-cart`、`feature/retail-points`） |
| `fix/*` | 修复分支（如 `fix/retail-stock-check`） |

### 2.2 Commit 消息规范

采用 Conventional Commits 格式：

```
<type>(<scope>): <subject>
```

**type 类型：**

| type | 说明 |
|------|------|
| feat | 新功能 |
| fix | 修复 Bug |
| docs | 文档变更 |
| style | 代码格式（不影响逻辑） |
| refactor | 重构 |
| perf | 性能优化 |
| test | 测试 |
| chore | 构建/工具变更 |

**scope 范围：**

| scope | 说明 |
|------|------|
| api | 后端 API |
| retail | 零售端（Taro 小程序） |
| admin | 管理后台 |
| db | 数据库 |
| shared | 共享代码 |

**示例：**
```

feat(retail): add WeChat mini-program login with wx.login
feat(api): add retail order creation endpoint
fix(retail): fix image not loading on WeChat mini-program
fix(retail): fix points calculation error in cart
chore: add Taro build scripts to root package.json
```

## 3. API 调用规范

### 3.1 Taro 零售端请求封装

```typescript
// retail/src/api/request.ts
import axios from 'axios'
import Taro from '@tarojs/taro'
import { useAuthStore } from '@/stores/useAuthStore'

const request = axios.create({
  baseURL: process.env.TARO_APP_API_BASE_URL,
  timeout: 15000,
  adapter: (config) => {
    return new Promise((resolve, reject) => {
      Taro.request({
        url: `${config.baseURL}${config.url}`,
        method: config.method?.toUpperCase() as any,
        data: config.data,
        header: {
          ...config.headers,
          'Content-Type': 'application/json',
        },
        success: (res) => {
          resolve({
            data: res.data,
            status: res.statusCode,
            statusText: res.statusCode === 200 ? 'OK' : 'Error',
            headers: res.header,
            config,
          })
        },
        fail: (err) => {
          reject(err)
        },
      })
    })
  },
})

request.interceptors.request.use((config) => {
  const authStore = useAuthStore()
  if (authStore.token) {
    config.headers.Authorization = `Bearer ${authStore.token}`
  }
  return config
})

request.interceptors.response.use(
  (response) => {
    const { data } = response
    if (data.code !== 0) {
      Taro.showToast({ title: data.message || '请求失败', icon: 'none' })
      return Promise.reject(new Error(data.message))
    }
    return data
  },
  (error) => {
    if (error.response?.status === 401) {
      const authStore = useAuthStore()
      authStore.logout()
    }
    Taro.showToast({ title: '网络异常，请稍后重试', icon: 'none' })
    return Promise.reject(error)
  }
)

export default request
```

## 4. 状态管理规范

### 4.1 Pinia Store 规范（Taro 零售端）

```typescript
// retail/src/stores/useAuthStore.ts
import { defineStore } from 'pinia'
import { ref } from 'vue'
import Taro from '@tarojs/taro'
import request from '@/api/request'

interface RetailUser {
  id: number
  nickname: string
  avatar: string
  phone: string
  points: number
}

export const useAuthStore = defineStore('auth', () => {
  // state
  const token = ref(Taro.getStorageSync('token') || '')
  const user = ref<RetailUser | null>(null)

  // actions
  async function wxLogin() {
    if (process.env.TARO_ENV !== 'weapp') return
    const { code } = await Taro.login()
    const res = await request.post('/api/auth/wx-login', { code })
    token.value = res.data.token
    user.value = res.data.user
    Taro.setStorageSync('token', token.value)
  }

  async function smsLogin(phone: string, code: string) {
    const res = await request.post('/api/auth/sms-login', { phone, code })
    token.value = res.data.token
    user.value = res.data.user
    Taro.setStorageSync('token', token.value)
  }

  function logout() {
    token.value = ''
    user.value = null
    Taro.removeStorageSync('token')
    Taro.reLaunch({ url: '/pages/login/index' })
  }

  return { token, user, wxLogin, smsLogin, logout }
})
```

### 5.3 组件编写原则

- 单一职责：一个组件只做一件事
- Props 类型化：使用 TypeScript interface 定义 props
- 事件命名：`on` + 动词（如 `onEdit`、`onDelete`、`onSelect`）
- 插槽（Vue）：用于灵活的内容分发
- 无副作用：组件不直接调用 API（通过 props 或 store 获取数据）

## 7. 错误处理规范

### 7.1 API 层

| 层级 | 处理方式 |
|------|---------|
| Workers 全局 | errorHandler 中间件捕获所有未处理异常 |
| 业务逻辑 | 返回具体 code + message |
| 数据库操作 | try/catch，返回 500 + 通用错误信息 |

### 7.2 前端层

| 场景 | 处理方式 |
|------|---------|
| 网络异常 | `Taro.showToast` 提示 "网络异常" |
| 401 未登录 | 清除 Token → `Taro.reLaunch` 跳转登录页 |
| 403 无权限 | `Taro.showToast` 提示 "无权限" |
| 业务错误（code != 0） | `Taro.showToast` 显示服务端 message |
| 表单校验 | 字段级错误提示（NutUI Form / 自定义校验） |

## 8. 性能规范

| 优化项 | 实现方式 |
|--------|---------|
| 图片懒加载 | NutUI Image 组件 `lazy-load` 属性 |
| 长列表优化 | 虚拟列表（Taro VirtualList）或分页加载，每页 20 条 |
| 请求缓存 | 首页数据缓存至 `Taro.setStorageSync`，设置过期时间 |
| 请求防抖 | 搜索输入 300ms 防抖 |
| 组件按需加载 | Taro 页面级分包加载（subPackages） |
| 组件按需引入 | `unplugin-vue-components` 自动按需加载 NutUI |
| 包体积优化 | 避免引入完整 lodash，使用 lodash-es 或独立包 |

## 9. 安全规范

| 安全项 | 规范 |
|--------|------|
| 密钥管理 | 所有密钥通过环境变量注入，禁止硬编码 |
| Token 存储 | 零售端使用 `Taro.setStorageSync`，Admin 端使用 `localStorage` |
| 微信密钥 | `WX_SECRET` 仅存在于服务端环境变量，严禁客户端暴露 |
| 用户输入 | 前端校验 + 后端 zod schema 校验 |
| 文件上传 | 前端 + 后端双重校验类型和大小 |
| 数据权限 | API 层校验 user_id 归属，防止越权访问 |
| 日志 | 禁止打印敏感信息（密码、Token、密钥） |
